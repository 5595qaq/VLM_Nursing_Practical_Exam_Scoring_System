# CHANGELOG

## 0.3（rubric 1.1）

處理時間取樣：開場影格每 2–4 秒一張、zoom 只看模型挑的瞬間，不到 1 秒的關鍵動作可能被錯過（VID_0083 的步驟 14 就是只憑 02:21 一格判錯）。

- **`scripts/motion_peaks.py`：** 每個任務開始時，以每秒 15 格分析區間內 hands_box 的畫面變化，列出最多 8 個動作峰值（相隔至少 0.5 秒）寫進任務說明；只表示「這裡有動作」，不代表是哪個動作。算不出來時照常評分，只是沒有峰值。
- **`burst` 動作（`scripts/burst.py`）：** 在 0.3–3 秒內平均取 3–12 張原始解析度的局部畫面（`region` 規則同 zoom），每組最多 3 次；證據格式 `burst@a-b #k`。
- **SKILL.md：** 先看動作峰值、在峰值附近用 burst 或相鄰時間點的 zoom 確認短動作；手部姿勢判錯誤前要在相隔約 0.2–0.5 秒的兩張以上畫面都清楚看到，只有一張看到時判正確並把 confidence 壓到 ≤ 0.6。

## 0.2（rubric 1.1）

第 2 階段：看畫面的評分 agent。

- **`SKILL.md`：** 評分 agent 的 system prompt。說明每條 visual 標準怎麼判（洗手七個動作、注視藥單、彈針要聲音和動作都有、先墊棉片才彈針、持毛筆、單手回套、空針放入包裝等），以及說明怎麼寫（實際看到／聽到什麼、mm:ss、哪裡沒做到、無法判定的原因）。
- **`actions.schema.json`＋`scripts/validate_grading_action.py`：** 每回合一個動作：`overview`、`zoom`、`clip`、`final`。時間只能落在任務區間前後 10 秒內；每組預算 overview 3、zoom 3、clip 2；`final` 必須剛好包含該組的標準，且每條通過 `validate_grading.py` 的同一套規則。
- **`scripts/clip.py`：** 從原檔剪出帶聲音的片段（裁到 context box、640 寬），原檔沒有音軌時回報 `has_audio: false`。
- **`scripts/eval_grading.py`：** 與人工標註表比對，人工說明合併「問題說明＋問題類型＋備注」；跳過空白、不適用、AI判定的列，預設排除 VID_0061、VID_0062、VID_0004、VID_0008。
- **`scripts/labels_to_segmentation.py`＋`sop_grading_cli --labels`：** 用人工標註的開始／結束秒數組出切分結果，調整評分 agent 時不必先跑 sop-video-skill。只取時間，不複製判定與說明；沒有時間的步驟給前後步驟之間的區間。`eval_grading.py` 另外列出有看畫面標準的步驟（類型 V），因為此時程式判定的標準等於照抄標註。
- **依 3 支真實影片（VID_0083、VID_0074、VID_0072）調整的 SKILL.md 規則：**
  - 小物件（酒精棉片、手指位置、持針姿勢）一定要用 zoom 確認；只靠 clip／overview 判定時 confidence ≤ 0.5。15b／25b 先 zoom 確認接合處真的有棉片。（VID_0083 的 15 原本把「手指捏住接合處」誤判成有棉片）
  - 寫明目前考場給藥紀錄單的位置（學生右後方牆上、點滴架旁的白色 A4 單張），看不清字不等於看不見。（VID_0074 的 29 原本說藥單不在畫面）
  - 「勿碰觸針心」只有 zoom 清楚看到指尖捏住針心桿才判錯誤；不明確判正確、confidence ≤ 0.6。（人工標註中步驟 14／24 從未扣分，兩支影片都出現誤報）
- **使用者確認的標準（rubric 1.1）：**
  - 注視藥單（2a／4a／29a）：看得到藥單時，沒去看或注視不到 10 秒（含眼神停留很短）一律判錯誤，並寫出原因；只有藥單真的不在畫面內才判無法判定。人工標註中這幾步多為「無法判定」，是因為 20250522 那批影片收集資料時大多沒拍到藥單，不是標準不同。
  - 3 讀（29）不能用看空瓶代替看藥單：只看空瓶再丟棄時 29a 判錯誤，說明寫「有看空瓶再丟棄，但沒有看藥單」。29a 設為 `key`：沒有看藥單整步錯誤。
  - 30a 改回 `key`：空針放在桌上（含影片結束時仍在桌上）或丟棄 → 整步錯誤。
  - 步驟 3 維持「有看藥物就算正確」：這是暫時和老師討論的標準，之後可能修改。
- 某一組任務失敗（連續不合格動作，或 Vertex AI 429 等 API 錯誤）只記在 `failed_tasks`，其他組照樣寫進結果，用 `--steps` 補跑即可。
- 後端 `sop_grading_service.py` 把待判定標準依 `window_steps` 分組，每組一段短對話；`python -m app.sop_grading_cli` 在本機對單支影片執行轉檔 → 切分 → 評分，`--steps` 只重評指定步驟。

## 0.1（rubric 1.0）

第 1 階段：評分標準與程式判定，尚未有評分 agent（SKILL.md、動作格式、`clip` 片段在第 2 階段加入）。

- **`rubric.json`：** 30 步的評分標準，每條標準分成三類：
  - `program`：由切分結果判定（步驟有沒有偵測到、洗手是否 ≥ 15 秒）；
  - `visual`：交給評分 agent 看畫面，`window_steps` 決定要看哪段影片；`audio: true` 的彈針（15b、17a、25b、27a）要連聲音一起判斷；1b 洗手七個動作要每 0.5 秒一格；
  - `not_visible`：影片看不到（藥物是否正確、針頭斜面、刻度等），固定輸出「無法判定」，不影響步驟判定。
  - 步驟 11 已自評分表移除，輸出「不適用」。
- **步驟判定由程式彙整（`scripts/rubric.py` 的 `aggregate`）：** `key` 標準錯誤 → 錯誤；有標準判部分正確，或有錯誤也有正確 → 部分正確；只有錯誤 → 錯誤；尚有待判定 → 待判定；有無法判定 → 無法判定；其餘 → 正確。
- **`scripts/rules.py`：** 讀 sop-video-skill 的切分結果，判定 `program` 標準、為 `visual` 標準算出要看的區間（相關步驟區段的聯集，前後各 2 秒），並組出每步的說明。切分結果為 `not_performed` 的步驟，所有標準直接判「錯誤」。
- **`schema.json` 與 `scripts/validate_grading.py`：** 每條標準都要有說明；正確／部分正確（以及看畫面判的錯誤）的說明必須含 mm:ss 時間點；判定為正確／錯誤／部分正確時要附影格或片段引用；無法判定要寫原因。`--final` 另外拒絕還在「待判定」的標準。

- **步驟 30：** 30b 由針心處或針柄處放入空針包裝都給分。（0.1 曾把 30a 設為非 key；rubric 1.1 依使用者確認改回 key，見 0.2）
