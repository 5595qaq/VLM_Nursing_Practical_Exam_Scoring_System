# 2026-11-09 切分 draft 只送變動的列（draftpatch，sop-video-skill 1.5.7）

issue #150。結論：**折衷版**（只送變動的列、每 3 個動作重寫一次完整草稿）切分費用約少 42%，和標記表吻合的步驟數落在舊版自己重跑的變動範圍內，發布為 1.5.7。

費用都是目錄價（gemini-4-argon：input $4／cached $0.20／output $20 每百萬 token），實際帳單以新台幣計價。

## 動機

0.39 版以後 67 次紀錄的成本分析：切分佔總成本約 40%（$157／$388），其中 output $88。切分 agent 每回合都把 30 步的完整草稿重新輸出一次，約佔切分 output 的 65%；外部程式本來就會把最新草稿附回下一回合的 input。

## 做法

| 版本 | 做法 | commit |
|---|---|---|
| 1.5.6（舊版） | 每個動作的 `draft` 都是完整草稿 | main |
| 1.5.6-draftpatch.2 | 只寫新增或改變的列（沒有變動寫 `無變動`），`scripts/draft.py` 依第一欄合併，每回合附回合併後的完整草稿 | 681fa36 |
| 1.5.6-draftpatch.3（折衷版） | 同上，但每 3 個動作要重寫一次完整草稿（外部程式提醒；少寫步驟列會被退回） | 463e503 |
| 1.5.7 | .3 加上 code review 修正（完整重寫時備註整段取代、`刪除（說明）`、`步驟 5`／`15–17` 視為同一列、重寫回合的退回訊息） | 87e1be7 |

681fa36、463e503 是 rebase 前的 commit（紀錄記的是它們），保留在 tag `runs/draftpatch.2`、`runs/draftpatch.3`。

評分只跑 `--steps 1`（產生紀錄需要），比較的是切分：`sop-video-skill/scripts/eval.py` 對標記表，開始與結束都差 ≤ 3 秒（或狀態一致）算吻合（`ok`、`status_ok`、`ok_convention`、`ok_handoff`）。

- final 被退回（`unassigned_spans`）在三個版本都有；舊版紀錄 153 次切分中 67 次，和這次的改動無關（另見 issue #153／PR #154）。
