# 2026-11-09 評分每個任務只送用到的 criteria 檔（taskcrit，放棄）

issue #151。結論：**在 gemini-4-argon 上比原本貴**，程式已 revert，不合併；三支影片的紀錄留在 `runs/` 當負面結果。

## 動機

0.39 版以後 67 次評分紀錄的成本分析（目錄價 input $4／cached $0.20／output $20 每百萬 token）：評分每次呼叫都送約 1.72 萬 token 的固定 system prompt（SKILL.md＋全部 criteria/＋sop_steps.md＋actions.schema），佔評分 input 的 75%；一個任務只判幾條標準，只用到 1–2 個 criteria 檔。

做法（commit 3245d60、89c41ea，評分 SKILL `0.41-taskcrit.1`，rubric 1.25）：system prompt 前面放共用部分（各任務相同），後面只接標題列出這個任務標準的 criteria 檔。每個任務的 system prompt 平均縮短到原本的 68%（字數）。預期共用的前段仍會命中 Gemini 的隱式快取。

## 原因

gemini-4-argon 的隱式快取看起來以**整份 system instruction** 為單位，而且同一份要被送過幾次之後才建立（2026-11-09 的探測：同一份 system prompt 連送時，前 3–4 個請求都沒命中）。原本所有任務共用同一份 system prompt，第 2 回合以後幾乎都命中；改成每個任務不同之後，一個任務只有 1–3 回合，快取永遠建不起來，連同一任務的第 2 回合也沒命中。

另一種做法是 system prompt 保持共用（只放共用部分），任務的 criteria 檔放進 user 訊息開頭。估算只省約 1.5%：原本 criteria 那段大多已經命中快取（每 token $0.20），搬到 user 訊息後變成全價（$4），抵掉縮短 system prompt 的好處。不值得再跑。

## 同一天的快取探測（不在 repo 裡的腳本，純文字或合成媒體，不含學生畫面）

為了查「評分第 1 回合只有 29% 命中快取（第 2 回合以後 84%）」：

- 純文字，固定開頭約 1.72 萬 token、後面接不同的任務文字：一開始同時送出的 3 個請求都沒命中（快取還沒建立）；建立後，A（固定開頭在 system）7/9、B（固定開頭自成一個 user 回合＋固定的 model 回覆）9/9。
- 加上合成圖片或影片片段：A 圖片 4/6、片段 5/6；B 圖片 0/6、片段 6/6。B 不能拿來改善帶圖片的請求。
