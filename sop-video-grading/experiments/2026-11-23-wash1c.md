# 01 洗手 1c：看實際接觸物品的時點（wash1c.1）

從 #186 拆出（維護者接手 #186，2026-11-23 決定採用，D-01-05）。分支版本：評分 SKILL `0.46-wash1c.2`／rubric `1.30-wash1c.2`（.1 是 #186 拆出時的版本）。

## 改了什麼

- 1c 從程式判定（切分裡最早的後續步驟起點 vs 洗手結束）改成評分 agent 看畫面：列出實際接觸物品的時點，早於洗手結束超過 1 秒才錯誤，看紀錄單不算接觸。
- 1c 區間從影片開頭開始。

## wash1c.2（review 修正，2026-11-23）

#190 code review 的三個重要問題：

1. **1c 和 1a、1b 同一個任務，洗手任務的區間會從 0 秒開始**：洗手在約 58 秒之後才結束時，就沒有 2 fps 的開場片段，1a、1b 證據不足。→ 1c 改成自己一個任務。1c 任務看不到 1a 的計時，所以評分 agent 只列接觸時點，**所有任務做完後由程式（`rules.build_step`）用 1a 的洗手結束比較並決定 1c 的判定**；1a 無法判定時 1c 無法判定。原本「只重評 1c 時帶上 1a 的 span」那條路徑實際上跑不到，已移除。
2. **沒看洗手前的畫面也能判 1c 正確**：→ 沒有看到洗手結束前的接觸時（`times` 為 `[]`，或只列洗手後的接觸），任務裡看過的 clip（開場片段算整個任務區間）要涵蓋影片開頭到最後一次洗手結束（切分步驟 1 最後一段的結束），中間空隙不超過 1 秒，否則退回。洗手很晚、這段超過 clip 預算（2 段 × 60 秒）時，評分 agent 只能列出看到的接觸，或判無法判定並轉人工複核。
3. **`eval_grading.py` 會讀說明裡的「00:00–洗手結束」，步驟 1 的時間比對幾乎一定算對**：→ 步驟 1 的時間比對不拿 1c 的時間。標記表的步驟 1 時間是洗手時段；1c 的接觸時點不是洗手時段，放進來也會造成誤判一致。

修正後再 review 一次，又找到並修正：
- 切分沒有偵測到洗手時，涵蓋檢查會因時間是 None 當掉 → 改用任務區間結束。
- 只列洗手後的接觸時不檢查涵蓋 → 現在也要檢查。
- 洗手很晚時 1c 永遠不能判正確（clip 預算蓋不完）→ 退回訊息和任務說明都改成要求判無法判定並轉人工複核。
- 1c 單獨重評時任務名稱會變成 `1`，續跑找不到 checkpoint、還會覆蓋 1a/1b 的對話紀錄 → 名稱固定為 `1-1c`。
- 涵蓋只要求到洗手開始，洗手中的接觸看不到 → 改成到洗手結束。
- 1c 判無法判定時列出的觀看時段會被 eval 當成步驟 1 的時間 → eval 完全不拿 1c 的時間。

小問題也一起修了：validate_grading_action 的 docstring 寫上 1c 的規則；測試名稱改成和內容相符。

和 #198（1a 分段相加）的關係：比較用的洗手結束改由 `rubric.wash_end` 讀，1a 用 `span` 或多段 `times` 都可以，後合併的不必再改這裡。
