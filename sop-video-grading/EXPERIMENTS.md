# 評分 agent 實驗紀錄

調整評分 agent 時做過的對照實驗、結論、已確認的標準定義，以及結論是否已經改進程式。

## 2026-10-19 手部姿勢：取樣方式與 MediaPipe

### 問題

評分 agent 判手部姿勢（持毛筆、單手回套、碰觸針心、夾瓶）時，同一組畫面跑兩次可能得到相反的判定（例如 VID_0074 步驟 12）。我們想知道是哪個原因：

- 取樣時間點不對：關鍵畫面落在兩格之間。
- 解析度不夠。
- 模型不知道標準姿勢長什麼樣子。

並比較 v0.3 加入的動作峰值＋burst 和 MediaPipe 手部骨架是否有幫助。

### 做法

- 案例：共 39 個。VID_0083／0074／0072 的 9 條手部姿勢標準（10b、12a、13a、14a、18b、19b、22b、24a、28b）有 27 個；另外加入 VID_0073／0076／0089／0111／0118／0134 各自被人工標錯誤的步驟 22 或 28，每支再配一個同類型的正確步驟，共 12 個。全部案例中人工判正確 32 個、錯誤 7 個。
- 每個案例的判定區間與手部裁切框固定（區間取人工標註時間 ±2 秒，和 `rules.py` 相同）。每次給 Gemini 一張 8 格的拼圖，只呼叫一次就判定（不是完整的 agent 多回合流程），同樣條件重複 3 次。
- 實驗程式放在本機暫存資料夾，沒有加入 repo。

| 組別 | 圖片 | prompt |
|---|---|---|
| A 對照 | 區間內等距 8 格 | 有「錯誤要兩格以上清楚看到」規則 |
| B | 最強兩個動作峰值前後各連拍 4 格（每 0.3 秒） | 同 A |
| C | A 的同一組圖，疊上 MediaPipe 手部骨架 | 同 A，加骨架說明 |
| D | B 的同一組圖，疊上 MediaPipe 手部骨架 | 同 C |
| E | 等距 8 格，區間結尾延伸到下一步的前 6 秒 | 同 A |
| F | A 的同一組圖 | **拿掉**兩格規則 |
| A＋程式檢查 | A 的回答；錯誤沒有引用 ≥2 格（或 2 個相鄰格）就改判正確 | — |
| A＋連拍確認 | A 判錯誤時，再送一張引用格前後的連拍（每 0.25 秒），連續兩格以上看到同樣的問題才維持錯誤 | — |

### 結果

| 組別 | 一致 | 錯誤召回 | 誤報 | 3 次判定相同的案例 |
|---|---|---|---|---|
| **A 對照** | **75%** | 10/21 | 12/96 | 36/39 |
| B 峰值＋連拍 | 45% | 0/21 | 14/96 | 33/39 |
| C 等距＋MediaPipe | 68% | 8/21 | 19/96 | 35/39 |
| D 峰值＋連拍＋MediaPipe | 38% | 1/21 | 17/96 | 34/39 |
| E 延伸區間 | 68% | 10/21 | 25/96 | 30/39 |
| F 拿掉兩格規則 | 73% | 12/21 | 20/96 | 33/39 |
| A＋程式檢查（≥2 格） | 75% | 10/21 | 12/96 | 36/39 |
| A＋程式檢查（相鄰 2 格） | 74% | 9/21 | 12/96 | 36/39 |
| A＋連拍確認 | 76% | 10/21 | 11/96 | 37/39 |

整個實驗約用 421 萬 input、10.5 萬 output token。

### 結論

- **峰值＋連拍不適合判手部姿勢。** 動作峰值抓到的是手在大幅移動（伸手拿東西、放下針套）的時刻，而姿勢要在手穩定持握時才看得清楚。這個方法仍可能適合不到 1 秒的短動作（彈針、碰觸瞬間），但這次沒有測到。
- **MediaPipe 骨架疊圖會讓誤報變多。** 骨架線遮住了手指和針筒的接觸位置。它推測的左右手也常常標錯，所以後來拿掉了 L/R 標籤。
- **延伸判定區間會把下一步的不同手勢拉進來**，例如 19b「單手回套」延伸到步驟 20「雙手轉 vial」，誤報因此翻倍。
- **prompt 裡的「錯誤要兩格以上清楚看到」有用**：拿掉後誤報從 12 增加到 20。
- **程式檢查引用格數沒有用**：模型判錯誤時本來就會引用兩格以上。
- **連拍確認的效益很小**：只少了 1 個誤報，token 卻多用約 23%。大部分誤報在連拍中也被「確認」，表示問題不在取樣，而在模型對姿勢的理解。

### 已確認的標準定義（2026-10-19）

- **14a／24a「未碰觸針心」**：手指貼在外筒或翼緣上算正確；只有碰到拉出、外露的推桿才算錯誤。

## 2026-10-20 手部姿勢第二輪：修正後比較放大方式

### 做法

同樣的 39 個案例、同樣的單次呼叫流程，重複 3 次。三組都套用以下修正：
- VID_0074、VID_0134 步驟 28 改用人工更正的時間。
- 24a 的裁切框上緣改為 0.03，涵蓋倒舉的 vial。
- prompt 加入 rubric 1.2 的「未碰觸針心」與「持毛筆」定義。

| 組別 | 做法 |
|---|---|
| A' | 等距 8 格（同第一輪 A，加上修正） |
| Z1 | 先給 A' 的圖，模型選 1–4 格和一個放大區域，再給原始解析度的放大圖判定（和評分 agent 的 `zoom` 動作相同，要呼叫兩次） |
| Z2 | 同樣 8 個時間點，每格以 MediaPipe 偵測到的雙手位置（加 60% 邊界）裁切放大，不疊骨架 |

### 結果

對照原始人工標註（人工判正確 32 個、錯誤 7 個）：

| 組別 | 一致 | 錯誤召回 | 誤報 | 判無法判定 | 3 次判定相同的案例 | input token |
|---|---|---|---|---|---|---|
| A 第一輪（未修正） | 75% | 10/21 | 12/96 | 13/117 | 36/39 | 63 萬 |
| A' 等距＋修正 | 80% | 13/21 | 8/96 | 8/117 | 36/39 | 66 萬 |
| **Z1 模型選放大區域** | **86%** | **15/21** | 8/96 | 3/117 | 33/39 | 147 萬 |
| Z2 MediaPipe 框選手部 | 74% | 9/21 | 9/96 | 12/117 | 37/39 | 66 萬 |

套用人工複查（VID_0076_19b 改為錯誤、VID_0073_22b 改為正確）後：A 80%、A' 85%、Z1 91%、Z2 79%。

第二輪共用 278 萬 input、5.8 萬 output token。

### 結論

- **修正本身就有效（A → A'）：** 一致率從 75% 升到 80%，誤報從 12 降到 8。VID_0074_24a（裁切框）、VID_0072_24a 與 VID_0083_13a（定義）都從錯誤改判為正確，兩個步驟 28 改用正確時間後也抓到了錯誤。
- **讓模型自己選區域放大最準（Z1）：** 一致率 86%，判無法判定的次數最少，但 token 是 A' 的 2.2 倍，3 次判定也比較不穩定（33/39）。它選的區域不一定對準手：只涵蓋 MediaPipe 手部範圍的 48%（平均），有一半以上的次數涵蓋不到一半。即使如此，結果仍比自動框選好。
- **MediaPipe 自動框選手部沒有幫助（Z2）：** 74%，比 A' 還低。框是以雙手為中心，常常切掉針筒、vial 或另一隻手，而這些正是判斷所需的器材。
- 這和評分 agent 的設計一致：先看等距 overview，再用 `zoom` 放大確認。所以不需要加入 MediaPipe。
- **還沒解決的案例：**
  - VID_0073_22b：模型 12 次都判正確。使用者 2026-10-20 重看影片確認：學生以拇指與食指、中指握住空針的針筒外管，符合持毛筆方式；判定區間（04:18–04:29）也正確。模型判正確才是對的，人工標註的「錯誤」有誤。
  - VID_0134_28b：改用正確時間後，A' 和 Z2 都判正確；Z1 有一次判無法判定，原因是學生的左手被乾洗手液瓶擋住。
  - VID_0089_18b（人工判正確）：A' 3 次都判錯誤，說手抓在推桿上；Z1 放大後多數判正確，認為是推入液體時才把食指移到尾端。

### 建議與進度

- [x] 維持評分 agent 的「overview → zoom」流程，不加入 MediaPipe（第二輪 Z2 比等距還差）。
- [x] `SKILL.md` 強調判持握姿勢時一定要 zoom，而且要對準握著器材的那隻手（Z1 的放大區域常常沒對準）：已寫入 0.4。
- [x] 人工確認 VID_0073_22b：模型判正確才是對的，人工標註有誤，不需要附參考畫面。
- [x] 用完整的評分 agent 流程重跑 3 支影片的手部姿勢步驟（10、12、13、14、18、19、22、24、26、28），確認 rubric 1.2／SKILL.md 0.4 的效果（2026-10-20）：手部姿勢步驟全部和人工一致，只有 VID_0074 步驟 28 判部分正確（人工標錯誤，見「待老師確認」）。全部步驟 72/87、錯誤召回 9/9、誤報 2/67；3 支共用約 72 萬 input token。
